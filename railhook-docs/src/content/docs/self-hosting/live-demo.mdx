Use this page to turn on the live demo: a **Try the live demo** button that opens the real dashboard, signed in to a sample organization, for anyone who clicks it. It is how railhook.io shows the product before a sign-up. A self-hosted install does not need it, and does not have it unless you turn it on.

## What a visitor gets

The demo is one organization, **Acme Inc.**, with one project, **Acme Shop**:

- four endpoints with their subscriptions, including a partner endpoint that fails now and then, so there are retried deliveries and a Failed Messages entry to look at;
- a Stripe source and a GitHub source, with verified incoming events forwarded to their destinations;
- about a day and a half of traffic, so the dashboard and analytics always show the last 24 hours.

A visitor can open every screen and read everything in it. They cannot change anything.

## Why it is off by default

The demo hands a session to anyone who asks for one. On a deployment that serves only your own team that is an anonymous way in you have no reason to open, so with `DEMO_ENABLED=false`, the default:

- no demo organization is created;
- the entry points on the landing page, on `/pricing` and in the **Developers** menu are hidden;
- the session endpoint, `POST /api/v1/public/demo/session`, answers `404`.

## Turn it on

<Steps>

1. **Set the variable** with the helper, which writes it to `.env`:

   ```bash
   printf 'DEMO_ENABLED=true\n' | ./railhook settings
   ```

2. **Recreate the containers** so both the API and the dashboard read it:

   ```bash
   ./railhook start
   ```

   The API creates the demo organization as it starts. The dashboard reads the same variable for its entry points, so set it once for both.

3. **Open `/demo`** on your Railhook address. It opens a session and takes you to the dashboard.

</Steps>

On Kubernetes, set both halves in the Helm values:

```yaml title="values.yaml"
api:
  env:
    DEMO_ENABLED: "true"
ui:
  publicDemo: true
```

## What keeps it read-only

A demo session is an access token for the demo organization with the **Viewer** role, and nothing more:

- **Every change is refused on the server**, not only hidden in the dashboard. A request from a demo session with any method other than `GET`, `HEAD` or `OPTIONS` is answered `403`, whatever the endpoint — API keys, members, settings, billing, replay, sending events, portal sessions, connected apps, the visitor's own profile. Exports are refused too, although they are reads. The only exceptions change nothing of the demo's: signing out, opening a new demo session, and the public site's contact form and webhook tester.
- **It cannot be extended.** There is no refresh token behind it. It lasts `DEMO_SESSION_TTL_MINUTES` (30 by default), then the visitor is returned to the landing page and can open a new one.
- **It works only on the API.** A demo token is not accepted anywhere outside `/api/`.
- **Opening one is limited**: ten sessions a minute from one address, behind the registration CAPTCHA when you have configured one (`CAPTCHA_SECRET_KEY` and `CAPTCHA_SITE_KEY`).
- **Nothing is ever delivered.** Every URL in the demo is on a reserved `.example` host, every delivery and forward in it is already finished, and the demo's sources refuse incoming webhooks. The worker never has anything of the demo's to send.

## Keeping it current

The API rewrites the demo's history every `DEMO_REFRESH_INTERVAL_MINUTES` (60 by default), so it always ends at the present. The organization, its endpoints and sources are created once and left as they are; only the events, deliveries and incoming events are replaced.

The demo is kept out of the deployment's own numbers: the [platform admin](/docs/self-hosting/platform-admin/) overview does not count its organization, account or traffic, and its Failed Messages do not raise the `webhook_dlq_depth` alert.

## Turning it off

Set `DEMO_ENABLED=false` and run `./railhook start`. No new session can be opened and the entry points disappear; a session already open lasts until it expires. The demo organization stays in the database, unused, and is no longer refreshed.

All three variables are in the [configuration reference](/docs/self-hosting/configuration/), and the session endpoint in the [API reference](/docs/api-reference/).
