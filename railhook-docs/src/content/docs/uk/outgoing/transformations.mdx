Трансформація перетворює вміст події на тіло запиту, якого очікує конкретний отримувач. Збережена подія лишається незмінною; змінюється лише тіло доставки.

## Шаблон

Трансформація — це JSON-документ, рядкові значення якого можуть містити JSONPath-вирази в плейсхолдерах `${…}`. Плейсхолдери обчислюються за вмістом події; усе інше копіюється як є.

```json title="Шаблон"
{
  "id": "${$.orderId}",
  "customer": {
    "email": "${$.customer.email}",
    "plan": "${$.subscription.plan_name}"
  },
  "amount_cents": "${$.amount}",
  "note": "Order ${$.orderId} from Railhook"
}
```

| Як записано | Результат |
|---|---|
| Рядок, що складається рівно з одного виразу, `"${$.amount}"` | Значення, на яке вказує вираз, зі своїм типом: число лишається числом, об'єкт — об'єктом. |
| Вираз усередині іншого тексту, `"Order ${$.orderId} from Railhook"` | Рядок із підставленим значенням. |
| Шлях, який нічого не знаходить | `null`, якщо вираз займає все значення, і порожній рядок усередині тексту. Це не помилка. |

<Aside type="caution" title="Одруківка в шляху минає непоміченою">
Шлях, який нічого не знаходить, не ламає шаблон, тож необов'язкове поле лишається необов'язковим. Через те саме правило шлях з одруківкою мовчки дає `null`. Перш ніж підключати шаблон, перевірте його на реальному вмісті події.
</Aside>

Шаблон — це не скрипт. Він може прочитати вміст і переставити в ньому поля, але не вміє виконувати цикли, робити зовнішні виклики чи щось обчислювати.

## До чого підключають трансформацію

| До чого | Дія |
|---|---|
| Підписка, `transformationId` | Збережена трансформація, яку застосовують до кожної доставки цієї підписки. |
| Підписка, `payloadTemplate` | Вбудований шаблон; діє, коли `transformationId` не задано. |
| Правило, дія `TRANSFORM` | Замінює трансформацію підписки для подій, які підпадають під правило. Якщо трансформацію задають кілька таких правил, діє останнє. Див. [Правила](/docs/uk/outgoing/rules/). |
| Призначення, `transformationId` | Збережена трансформація, яку застосовують до вхідних вебхуків перед пересиланням. |
| Призначення, `payloadTransform` | Один JSONPath-вираз, наприклад `$.data`; діє, коли `transformationId` не задано. |
| Воркфлоу, вузол `transform` | Змінює структуру даних усередині воркфлоу. Див. [Воркфлоу](/docs/uk/outgoing/workflows/). |

## Коли трансформація спрацьовує

Трансформацію застосовують у кожній спробі, ще до обчислення підпису. Підпис охоплює вже трансформовані байти, тож отримувач, перевіряючи підпис, перевіряє саме те, що отримав.

Збережену трансформацію Railhook завантажує в момент спроби. Тож якщо виправити зламаний шаблон, це подіє на всі наступні спроби.

<Aside type="danger" title="Через зламаний шаблон оригінальний вміст не витече">
Якщо налаштовану трансформацію не вдається застосувати або `transformationId` вказує на відсутню чи вимкнену трансформацію, спроба вважається невдалою, і Railhook її повторює. Оригінальний вміст замість трансформованого ніколи не надсилається, бо саме трансформаціями часто вирізають персональні дані, перш ніж ті залишать систему. Кожна невдача збільшує лічильник `transform_failed_total`.
</Aside>

## Як створити й перевірити трансформацію

<Steps>

1. Створіть її. Поля `name` і `template` обов'язкові; шаблон може мати до 65 536 символів.

   ```bash
   curl -X POST "$RAILHOOK_URL/api/v1/projects/$PROJECT_ID/transformations" \
     -H "X-API-Key: $API_KEY" \
     -H "Content-Type: application/json" \
     -d '{"name":"Orders to CRM","template":"{\"id\":\"${$.orderId}\",\"amount_cents\":\"${$.amount}\"}"}'
   ```

2. Перевірте результат на вставленому вмісті через `POST /api/v1/projects/{projectId}/transform-preview`. Надішліть `inputPayload` і або `transformationId`, або вбудований `template`. Нічого не доставляється.

3. Змоделюйте доставку (пробний запуск) через `POST /api/v1/projects/{projectId}/transform-preview/delivery-dry-run`. Надішліть `payload`, трансформацію або `payloadTemplate`, а також `endpointId`. У відповіді буде трансформоване тіло, заголовки й підпис, які було б надіслано, а також назва й версія трансформації. Нічого не надсилається.

4. Підключіть трансформацію, задавши `transformationId` у підписці.

</Steps>

У панелі **«Студія трансформацій»** показує вміст і результат поруч і оновлює результат, щойно ви щось змінюєте.

Кожна зміна шаблону трансформації збільшує номер її версії.
