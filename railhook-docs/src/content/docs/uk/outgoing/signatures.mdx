Кожну доставку підписано секретом ендпоінта. Перевіряйте підпис, перш ніж обробляти запит: тоді ніхто, хто дізнався URL вашого ендпоінта, не зможе надсилати вам події.

## Дві схеми підпису

Доставка може мати два незалежні підписи того самого тіла. Які з них надсилати, визначає `signatureScheme` ендпоінта:

| `signatureScheme` | Які заголовки надсилаються |
|---|---|
| `BOTH` (типово) | `X-Signature` і заголовки Standard Webhooks. |
| `LEGACY` | Лише `X-Signature`. |
| `STANDARD` | Лише `webhook-id`, `webhook-timestamp`, `webhook-signature`. |

Отримувач просто ігнорує заголовки, яких не читає, тож перевіряйте будь-який із двох підписів. Залишайте ендпоінту одну схему лише тоді, коли другу вже ніхто не перевіряє.

## Заголовки кожної доставки

| Заголовок | Значення |
|---|---|
| `X-Signature` | `t=<unix-ms>,v1=<hex>`. Під час ротації секрету може містити другий `v1`. |
| `X-Timestamp` | Те саме значення, що й `t`: коли підписано цю спробу, у мілісекундах. |
| `X-Event-Id` | Ідентифікатор події. Кожен підписаний на неї ендпоінт отримує той самий ідентифікатор. |
| `X-Delivery-Id` | Ідентифікатор цієї доставки: однієї події на один ендпоінт. Однаковий в усіх спробах. |
| `X-Sequence-Number` | Позиція цієї доставки, якщо ввімкнено впорядковану доставку, інакше `0`. |
| `Idempotency-Key` | Однаковий в усіх спробах, тож за ним можна відкинути те, що ви вже обробили. |
| `webhook-id` | Ідентифікатор доставки. Входить до даних, які охоплює підпис Standard Webhooks. |
| `webhook-timestamp` | Коли підписано цю спробу, у **секундах**. |
| `webhook-signature` | `v1,<base64>`; якщо значень кілька, вони йдуть через пробіл. |

## Перевірка `X-Signature`

`v1` — це HMAC-SHA256 від рядка `<t>.<необроблене тіло>` байт у байт, де ключ — секрет ендпоінта; результат записано в hex малими літерами. `t` — у мілісекундах. SDK Railhook відхиляють мітку часу, яка відрізняється від поточного часу більш ніж на 300 секунд.

### За допомогою SDK

<Tabs syncKey="lang">
<TabItem label="Node.js">

```ts
import express from 'express';
import { constructEvent } from '@railhook/node';

const app = express();

// express.raw, not express.json: the signature covers the bytes that arrived.
app.post('/webhooks', express.raw({ type: 'application/json' }), (req, res) => {
  try {
    const event = constructEvent(req.body.toString('utf8'), req.headers, process.env.WEBHOOK_SECRET);
    // event.data is the parsed body; event.deliveryId is safe to deduplicate on.
    res.sendStatus(200);
  } catch {
    res.sendStatus(400);
  }
});
```

</TabItem>

### Без SDK

Та сама перевірка без бібліотек. Читайте всі `v1` у заголовку, а не лише перший.

<Tabs syncKey="lang">
<TabItem label="Node.js">

```js
import crypto from 'node:crypto';

export function verify(rawBody, header, secret) {
  let t;
  const candidates = [];
  for (const part of header.split(',')) {
    const [key, value] = part.split('=', 2);
    if (key === 't') t = value;
    if (key === 'v1') candidates.push(value);
  }
  if (!t || candidates.length === 0) return false;
  if (Math.abs(Date.now() - Number(t)) > 5 * 60 * 1000) return false;

  const expected = Buffer.from(
    crypto.createHmac('sha256', secret).update(`${t}.${rawBody}`).digest('hex'),
  );
  let ok = false;
  for (const candidate of candidates) {
    const given = Buffer.from(candidate);
    if (given.length === expected.length && crypto.timingSafeEqual(given, expected)) ok = true;
  }
  return ok;
}
```

</TabItem>
<TabItem label="Python">

```python
import hashlib
import hmac
import time

def verify(raw_body: bytes, header: str, secret: str) -> bool:
    t, candidates = None, []
    for part in header.split(","):
        key, _, value = part.partition("=")
        if key == "t":
            t = value
        elif key == "v1":
            candidates.append(value)
    if t is None or not candidates:
        return False
    if abs(time.time() * 1000 - int(t)) > 5 * 60 * 1000:
        return False

    expected = hmac.new(secret.encode(), f"{t}.".encode() + raw_body, hashlib.sha256).hexdigest()
    ok = False
    for candidate in candidates:
        if hmac.compare_digest(expected, candidate):
            ok = True
    return ok
```

</TabItem>
<TabItem label="PHP">

```php
<?php
function verify(string $rawBody, string $header, string $secret): bool
{
    $t = null;
    $candidates = [];
    foreach (explode(',', $header) as $part) {
        [$key, $value] = array_pad(explode('=', $part, 2), 2, '');
        if ($key === 't') {
            $t = $value;
        } elseif ($key === 'v1') {
            $candidates[] = $value;
        }
    }
    if ($t === null || $candidates === []) {
        return false;
    }
    if (abs((int) (microtime(true) * 1000) - (int) $t) > 300000) {
        return false;
    }

    $expected = hash_hmac('sha256', $t . '.' . $rawBody, $secret);
    $ok = false;
    foreach ($candidates as $candidate) {
        if (hash_equals($expected, $candidate)) {
            $ok = true;
        }
    }
    return $ok;
}
```

## Перевірка заголовків Standard Webhooks

Заголовки Standard Webhooks відповідають відкритій специфікації, тож перевірити їх може будь-яка готова бібліотека. Від `X-Signature` вони відрізняються трьома речами:

- Підписують рядок `<webhook-id>.<webhook-timestamp>.<необроблене тіло>`, тобто ідентифікатор теж входить до підпису.
- `webhook-timestamp` — у секундах, а не в мілісекундах.
- Хеш записано в base64, а не в hex, а ключ — це `standardWebhooksSecret` ендпоінта у форматі `whsec_<base64>`.

API повертає `standardWebhooksSecret` разом із `secret` під час створення ендпоінта й ротації секрету. SDK приймають і секрет без префікса й використовують його як є, тож секрет не в тому форматі дасть помилку неправильного підпису, а не повідомлення про неправильний формат.

<Tabs syncKey="lang">
<TabItem label="Node.js">

```ts
import express from 'express';
import { verifyStandardWebhook } from '@railhook/node';

app.post('/webhooks', express.raw({ type: 'application/json' }), (req, res) => {
  try {
    verifyStandardWebhook(req.body.toString('utf8'), req.headers, process.env.RAILHOOK_WHSEC);
  } catch {
    return res.sendStatus(400);
  }
  const data = JSON.parse(req.body.toString('utf8'));
  return res.sendStatus(204);
});
```

</TabItem>

from fastapi import HTTPException, Request, Response

    return Response(status_code=204)

## Ротація секрету без збоїв в отримувача

<Steps>

1. Викличте `POST /api/v1/projects/{projectId}/endpoints/{id}/rotate-secret`. Відповідь містить новий `secret` і `standardWebhooksSecret`.

2. Протягом перехідного періоду ендпоінта (типово 24 години) кожну доставку підписують і новим, і старим секретом. `X-Signature` містить по одному `v1` для кожного секрету, а `webhook-signature` — по одному значенню через пробіл:

   ```http
   X-Signature: t=1735689600000,v1=8f2a41c7…new,v1=3b90de55…retired
   ```

3. Розгорніть новий секрет в отримувача будь-коли протягом цього періоду. Коли він мине, доставки підписуватимуться лише новим секретом.

</Steps>

<Aside type="caution" title="Типові помилки">
- Перевіряйте тіло байт у байт, як воно прийшло. Якщо його розібрати й знову серіалізувати, хеш вийде інший.
- Порівнюйте за сталий час: `timingSafeEqual`, `hmac.compare_digest`, `hash_equals`.
- Відхиляйте застарілу мітку часу, щоб перехоплений запит не можна було надіслати повторно пізніше.
- Читайте всі `v1` або всі значення через пробіл. Якщо брати лише одне, під час ротації справжній запит виглядатиме як підроблений.
- Не плутайте одиниці: `X-Timestamp` — у мілісекундах, `webhook-timestamp` — у секундах.
</Aside>
