Воркфлоу — це граф кроків, який запускається, коли надходить подія, або коли ви запускаєте його вручну. Кожен крок отримує результат попереднього. У панелі є візуальний конструктор, а той самий воркфлоу можна створити й через API.

## Як виконується воркфлоу

- **Тригер** запускає виконання і передає на вхід `data` події.
- Вузли виконуються в топологічному порядку: вузол стартує лише тоді, коли завершилися всі вузли, від яких він залежить.
- Вихідні дані кожного вузла стають вхідними для вузлів, з якими він з'єднаний. Вузол із кількома вихідними ребрами передає дані в кожну гілку паралельно.
- Якщо умови вузла `filter` не виконано, усе, що йде після нього, пропускається. Вузол `branch` спрямовує виконання ребром `true` або `false`.
- Кожен крок записує свій статус, вхідні й вихідні дані та тривалість, тож виконання можна переглянути крок за кроком. Список виконань повертає `GET /api/v1/projects/{projectId}/workflows/{id}/executions`.

## Тригери

| `triggerType` | Коли запускається |
|---|---|
| `WEBHOOK_EVENT` (типово) | Для кожної події, тип якої збігається з `triggerConfig.eventTypePattern`. Без шаблону — для кожної події в проєкті. На одну подію воркфлоу виконується щонайбільше один раз. |
| `MANUAL` | Коли ви викликаєте `POST /api/v1/projects/{projectId}/workflows/{id}/trigger`. JSON-тіло запиту стає вхідними даними. |

Увімкнути чи вимкнути воркфлоу можна через `PATCH /api/v1/projects/{projectId}/workflows/{id}/toggle`.

## Типи вузлів

| `type` | Що робить | Налаштування в `data` |
|---|---|---|
| `webhookTrigger` | Точка входу. Передає вхідні дані тригера далі. | немає |
| `filter` | Пропускає виконання далі, лише якщо умови виконано; інакше наступні вузли пропускаються. | `conditions`, те саме дерево умов, що й у [правилах](/docs/uk/outgoing/rules/#умови) |
| `branch` | Перевіряє умови й веде виконання ребром `true` або `false`. Якщо умов немає — `true`. | `conditions` |
| `transform` | Змінює структуру даних. Якщо задано обидва поля, перевагу має збережена трансформація; якщо її не знайдено, крок завершується помилкою. | `transformationId` або `template` із плейсхолдерами `{{field.path}}` |
| `http` | Викликає URL і передає відповідь далі. | `url` (обов'язкове), `method` (типово `POST`), `headers`, `body` (типово — вхідні дані), `timeout` у секундах, від 1 до 60, типово 30 |
| `slack` | Надсилає повідомлення у вхідний вебхук Slack. | `webhookUrl`, `message`, `channel` |
| `delivery` | Доставляє дані на наявний ендпоінт звичайним конвеєром доставки, з повторними спробами. Дані записуються як подія в проєкті ендпоінта й, як і будь-яка інша подія, зараховуються до подій місяця. | `endpointId` (обов'язкове), `eventType` (типово `workflow.delivery`) |
| `createEvent` | Надсилає в Railhook нову подію, яка далі, як і будь-яка інша, проходить правила й підписки та зараховується до подій місяця. Проєкт має належати вашій організації; воркфлоу, що вказує на будь-який інший, зберегти не вдасться. | `projectId`, `eventType` (обидва обов'язкові), `payloadTemplate` (типово — вхідні дані) |
| `delay` | Призупиняє виконання, не займаючи при цьому потік воркера. | `delaySeconds`, від 1 до 300, типово 5 |

## Як створити воркфлоу

Визначення складається зі списку `nodes`, де кожен вузол має `id`, `type` і свої `data`, та списку `edges` від `source` до `target`. Для ребра, що виходить із вузла `branch`, `sourceHandle` дорівнює `"true"` або `"false"`.

```bash
curl -X POST "$RAILHOOK_URL/api/v1/projects/$PROJECT_ID/workflows" \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Big orders to the fraud service",
    "enabled": true,
    "triggerType": "WEBHOOK_EVENT",
    "triggerConfig": { "eventTypePattern": "order.*" },
    "definition": {
      "nodes": [
        { "id": "start", "type": "webhookTrigger", "data": {} },
        { "id": "big", "type": "filter", "data": { "conditions": { "type": "predicate", "field": "amount", "operator": "GTE", "value": 1000, "valueType": "NUMBER" } } },
        { "id": "check", "type": "http", "data": { "url": "https://fraud.example.com/check", "method": "POST" } }
      ],
      "edges": [
        { "source": "start", "target": "big" },
        { "source": "big", "target": "check" }
      ]
    }
  }'
```

## Ліміти часу

| Ліміт | Типово |
|---|---|
| Одне виконання від початку до кінця | 600 секунд |
| Один вузол | 30 секунд |
| Вузол `http` або `slack` | 60 секунд |
| Вузол `createEvent` | 30 секунд |

## На що зважати

<Aside type="caution">
- URL вузла `http` проходить ту саму перевірку приватних адрес, що й ендпоінт; її налаштовують змінні `WEBHOOK_ALLOW_PRIVATE_IPS` і `WEBHOOK_ALLOWED_HOSTS`. Див. [Безпека ендпоінта](/docs/uk/outgoing/endpoint-security/#куди-можуть-іти-доставки).
- Вузол `slack` приймає лише URL, що починається з `https://hooks.slack.com/`.
- Кожен крок зберігає свої вхідні й вихідні дані як є. Усе секретне в даних можна буде прочитати в історії виконань, тож спершу замаскуйте це. Див. [Маскування PII](/docs/uk/platform/pii-masking/).
</Aside>
