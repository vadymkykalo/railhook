title: Прийміть перший вебхук
description: Підключіть сервіс як джерело, дайте йому ingress-адресу й пересилайте все, що надходить, у своє призначення.
---
import { Steps, Aside, CardGrid, LinkCard } from '@astrojs/starlight/components';

Railhook може приймати вебхуки від стороннього сервісу, перевіряти, що вони справді надійшли від нього, і пересилати їх у ваші сервіси. Вам знадобляться ідентифікатор проєкту та API-ключ. Усе це можна зробити й у панелі керування, в розділі **«Прийом вебхуків»**.

<Aside type="tip">
Хочете спершу подивитися, що саме надсилає сервіс, і лише потім його підключати? Безкоштовний [тестер вебхуків](https://railhook.io/tester) дає URL, який показує кожен отриманий запит, і обліковий запис для цього не потрібен.
</Aside>

```bash
export RAILHOOK_URL=https://railhook.io   # or your own instance
export RAILHOOK_API_KEY=...
export PROJECT_ID=...
```

<Steps>

1. **Створіть джерело**

   Джерело — це підключений сервіс разом із тим, що потрібно Railhook для перевірки його запитів.

   ```bash
   curl -X POST "$RAILHOOK_URL/api/v1/projects/$PROJECT_ID/incoming-sources" \
     -H "X-API-Key: $RAILHOOK_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{"name":"Stripe","providerType":"STRIPE","verificationMode":"PROVIDER","hmacSecret":"whsec_..."}'
   ```

   Типи провайдерів: `GENERIC`, `GITHUB`, `GITLAB`, `STRIPE`, `SHOPIFY`, `SLACK`, `TWILIO`. Режими перевірки:

   | Режим | Що перевіряється |
   |---|---|
   | `PROVIDER` | Власна схема підпису провайдера, обрана за його типом |
   | `HMAC_GENERIC` | HMAC-підпис необробленого тіла запиту; Railhook бере його із заголовка з префіксом, які ви налаштували |
   | `NONE` | Нічого. Вмикайте лише на час підключення провайдера |

2. **Передайте провайдеру ingress-адресу**

   Відповідь містить `ingressUrl` у вигляді `https://your-host/ingress/<token>`. Вставте її в налаштування вебхуків на боці провайдера.

   <Aside type="caution">
   Токен — єдине в адресі, що ідентифікує джерело, тож бережіть цю адресу, як облікові дані. Саме перевірка підпису не дає тому, хто дізнався цю адресу, підкидати події.
   </Aside>

3. **Додайте призначення**

   Призначення — це ваш URL, який отримує все, що приймає джерело, разом зі способом автентифікації на ньому.

   ```bash
   curl -X POST "$RAILHOOK_URL/api/v1/projects/$PROJECT_ID/incoming-sources/$SOURCE_ID/destinations" \
     -H "X-API-Key: $RAILHOOK_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{"url":"https://api.example.com/webhooks/stripe","authType":"BEARER","authConfig":"{\"token\":\"...\"}","enabled":true}'
   ```

   `authType` — одне зі значень `NONE`, `BASIC`, `BEARER`, `CUSTOM_HEADER`. Джерело пересилає кожен перевірений вебхук на кожне своє увімкнене призначення.

4. **Надішліть тестовий вебхук і простежте, як він надійде**

   Надішліть тестовий вебхук із панелі провайдера. Він з'явиться в розділі **«Події» → «Вхідні події»**, з одним пересиланням на кожне призначення. Пересилання, у якого закінчилися повторні спроби, потрапляє до розділу **Невдалі пересилання**.

</Steps>

## Що відповідає ingress

| Статус | Значення |
|---|---|
| `202` | Прийнято й збережено |
| `401` | Перевірку налаштовано, а підпис не збігся. Нічого не збережено |
| `403` | Організацію призупинено |
| `404` | Жодне джерело не має такого токена або його проєкт видалено |
| `410` | Джерело існує, але його вимкнено |
| `413` | Тіло запиту перевищує ліміт розміру для вхідних вебхуків |
| `429` | Вичерпано ліміт запитів джерела на секунду |

<Aside type="tip">
Railhook на власному сервері? Ingress-адреси починаються з вашої публічної адреси, `APP_BASE_URL`, яку інсталятор бере з `--domain`. `TUNNEL_INGRESS_BASE_URL` задавайте лише тоді, коли вебхуки надходять у Railhook на інший хост, ніж панель керування. Докладніше — у розділі [Конфігурація](/docs/uk/self-hosting/configuration/).
</Aside>
