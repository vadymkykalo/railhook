## Порівняння в таблиці

| | Railhook | Svix |
|---|---|---|
| Ліцензія сервера | MIT | MIT |
| Чого немає у відкритій версії | Нічого | App Portal і трансформацій |
| Надсилання вебхуків вашим клієнтам | Так | Так (Svix Dispatch) |
| Приймання вебхуків від провайдерів | Так, у тому самому продукті | Так, окремим продуктом (Svix Ingest) |
| Портал для клієнтів | Так, вбудовуваний, у відкритій версії | App Portal, лише в хмарі |
| OpenTelemetry | Ні | Так |
| SDK | Node.js, Python, PHP | 9 мов |
| Terraform-провайдер | Ні | Так |
| Сертифікації | Не заявлено | SOC 2, HIPAA |
| Тунель до localhost у CLI | Так | — |

Прочерк означає, що з перевірених сторінок Svix це однозначно не випливає. Це не твердження, що такої функції немає.

## Коли краще обрати Svix

- **Вам потрібен найзріліший портал для клієнтів.** App Portal від Svix уже роками працює в продакшні. [Портал для клієнтів](/docs/uk/outgoing/customer-portal/) у Railhook робить головне (ваші користувачі реєструють ендпоінти, вибирають типи подій, переглядають спроби й повторюють невдалі доставки), але налаштувати його вигляд можна лише кольором, логотипом, світлою чи темною темою та мовою.
- **Сертифікації потрібні вже зараз.** Svix заявляє SOC 2 і HIPAA. Railhook не заявляє жодної з них.
- **Ваш стек — не Node.js, Python чи PHP.** Svix має SDK для 9 мов і Terraform-провайдер. У Railhook три SDK і немає Terraform-провайдера; з інших мов доведеться викликати REST API напряму.
- **Вам потрібні трейси.** Svix експортує дані в OpenTelemetry. Railhook віддає метрики Prometheus, а трейсів не має.

## Коли краще обрати Railhook

- **Ви розгортаєте на власному сервері й хочете всі функції.** У відкритому сервері Svix немає App Portal і трансформацій. MIT-репозиторій Railhook — це весь продукт: вбудовуваний портал для клієнтів, трансформації, воркфлоу, порядок доставки для кожного ендпоінта, відтворення подій і маскування PII працюють на вашому сервері без жодного ліцензійного ключа.
- **Ви і надсилаєте, і приймаєте вебхуки.** У Railhook вихідні доставки вашим клієнтам і вхідні вебхуки від Stripe, GitHub, Shopify та інших проходять однаковий життєвий цикл спроб, мають одну панель керування й один список недоставлених повідомлень. Svix пропонує ці два напрямки як окремі продукти.
- **Ви хочете розробляти локально на справжніх вебхуках.** `railhook listen 3000` відкриває тунель із публічної адреси на ваш комп'ютер, тож тестовий вебхук провайдера потрапляє просто в код, відкритий у вашому редакторі. Див. [CLI](/docs/uk/tools/cli/).
- **Ваші приймачі вже перевіряють підписи Svix.** Railhook підписує вебхуки заголовками [Standard Webhooks](https://github.com/standard-webhooks/standard-webhooks), за тією самою схемою, яку перевіряють бібліотеки Svix, тож приймачі й далі працюватимуть, щойно отримають новий секрет.

## Перехід зі Svix

Застосунок Svix стає проєктом Railhook, повідомлення — подією, а типи подій на ендпоінті — підписками. Джерела й призначення Svix Ingest стають джерелами й призначеннями Railhook. Схема підпису однакова, тож можна надсилати кожну подію на обидві платформи, доки не переконаєтеся, що все працює, а потім припинити надсилання у Svix. У розділі [Перехід на Railhook](/docs/uk/resources/migrating/) є відповідність понять і план переходу без вікна обслуговування.
