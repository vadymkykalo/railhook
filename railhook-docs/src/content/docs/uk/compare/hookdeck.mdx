Ця сторінка допоможе обрати між Hookdeck і Railhook. Hookdeck — це два продукти: Event Gateway для приймання вебхуків і Outpost для їх надсилання. Railhook робить обидва в одному продукті, і сторінка порівнює його з кожною половиною.

<Aside title="Перевірено 2026-09-18">
Відомості про Hookdeck узято з [hookdeck.com/pricing](https://hookdeck.com/pricing) і [github.com/hookdeck/outpost](https://github.com/hookdeck/outpost) у тому вигляді, в якому вони були 18 вересня 2026 року. Продукти змінюються: перевірте їх, перш ніж вирішувати, і надішліть виправлення як pull request, якщо щось тут застаріло.
</Aside>

## Поряд

| | Railhook | Hookdeck Event Gateway | Hookdeck Outpost |
|---|---|---|---|
| Напрямок | Приймання й надсилання | Приймання | Надсилання |
| Ліцензія | MIT | Закритий код, лише SaaS | Apache-2.0 |
| Можна розгорнути на власному сервері | Так, усі функції | Ні | Так |
| Доставляє в черги й шини подій | Ні, лише HTTP | — | Так: SQS, Kafka, EventBridge, Pub/Sub, RabbitMQ та інші |
| Портал для клієнтів | Ні | — | Так |
| OpenTelemetry | Ні | — | Так |
| Безкоштовний CLI для локальної розробки | Так | Так, разом із Console | — |

Прочерк означає, що перевірені сторінки не дають однозначної відповіді або пункт не стосується цього продукту. Це не твердження, що функції немає.

## Коли кращий вибір — Hookdeck

- **Приймачі ваших клієнтів — черги, а не HTTP-сервіси.** Outpost доставляє в SQS, Kafka, EventBridge, Pub/Sub і RabbitMQ. Railhook доставляє лише через HTTP.
- **Вам потрібен портал, яким клієнти користуються самі.** Outpost має портал користувача. У Railhook поки немає порталу для клієнтів; ендпоінтами керуєте ви від їхнього імені.
- **Вам потрібні траси.** Outpost експортує OpenTelemetry. Railhook віддає метрики Prometheus, трас немає.
- **Ви приймаєте вебхуки й не хочете нічого обслуговувати.** Event Gateway — керований сервіс із платними планами. Railhook Cloud поки має лише безкоштовний план, тож обсяг понад його ліміти означає власний сервер.

## Коли кращий вибір — Railhook

- **Приймання має працювати на вашому сервері.** Event Gateway має закритий код і працює лише як SaaS від Hookdeck. Ingress, перевірка, пересилання й повтор подій у Railhook — усе в MIT-репозиторії, тож вебхукам провайдерів не треба проходити через третю сторону.
- **Ви приймаєте й надсилаєте.** Hookdeck ділить напрямки на два продукти з двома розгортаннями. У Railhook вхідні пересилання й вихідні доставки мають один життєвий цикл спроб, одну панель і один список невдалих повідомлень.
- **Ви самі вирішуєте, скільки зберігати вебхуки.** Railhook на власному сервері зберігає отримані вебхуки стільки, скільки ви налаштуєте, і будь-який із них можна знову відтворити на ваші сервіси. Див. [Зберігання та експорт даних](/docs/uk/resources/data-retention/).
- **Ви хочете перевірку провайдерів, не пишучи її.** Railhook сам перевіряє підписи Stripe, GitHub, GitLab, Shopify, Slack і Twilio та відхиляє підроблений вебхук із `401` ще до збереження. Див. [Перевірка вхідних вебхуків](/docs/uk/incoming/verification/).

## Перехід з Hookdeck

Джерело Event Gateway стає джерелом Railhook, а його призначення — призначеннями джерела. Призначення Outpost стає ендпоінтом Railhook. Спершу створіть джерело Railhook і його призначення, надішліть тестовий вебхук на ingress-адресу, а потім змініть на неї адресу вебхука в провайдера. [Перехід на Railhook](/docs/uk/resources/migrating/) містить повну відповідність понять.
