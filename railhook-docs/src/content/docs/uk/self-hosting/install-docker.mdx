Обидва способи запускають той самий `docker-compose.yml`. Інсталятор також генерує секрети й перевіряє конфігурацію до запуску.

<Tabs syncKey="install">
  <TabItem label="Інсталятор">
    <Steps>

    1. **Запустіть інсталятор**

       ```bash
       curl -fsSL https://railhook.io/install.sh | bash
       ```

       Він перевіряє Docker, Compose, пам'ять, диск і порт, потім створює `~/railhook`: `docker-compose.yml`, закріплений на останньому релізі, `.env` зі згенерованими секретами та допоміжний скрипт `railhook`. Далі запускає стек і чекає на API. Перший запуск виконує міграції й створює топіки Kafka, тож може тривати кілька хвилин.

    2. **Відкрийте панель керування**

       Перейдіть на `http://localhost` (або `http://<server-ip>`; додайте `:<port>`, якщо встановлювали з `--port`) і зареєструйтеся. Поштовий сервер не налаштовано, тож обліковий запис активний одразу.

    3. **Збережіть резервну копію `.env`**

       `WEBHOOK_ENCRYPTION_KEY` і `WEBHOOK_ENCRYPTION_SALT` із цього файлу шифрують кожен секрет ендпоінта в базі даних. Якщо відновити резервну копію бази без цього файлу, ви отримаєте рядки, які вже ніщо не прочитає.

    </Steps>

    ### Параметри інсталятора

    Передавайте параметри через конвеєр за допомогою `bash -s --`:

    ```bash
    curl -fsSL https://railhook.io/install.sh | bash -s -- --dir /opt/railhook --port 8080
    ```

    | Параметр | Дія |
    |---|---|
    | `--dir <path>` | Куди встановити. Типово `~/railhook` |
    | `--version <tag>` | Реліз, на якому закріпити встановлення, `v2.12.0` або новіший. Типово — останній реліз |
    | `--port <port>` | Єдиний опублікований порт. Типово `80`, або `8080` з `--behind-proxy` |
    | `--domain <host>` | Працювати на цьому домені через HTTPS. Див. [Домен і HTTPS](/docs/uk/self-hosting/domain-https/) |
    | `--behind-proxy` | Разом із `--domain`: TLS термінує ваш власний зворотний проксі, а панель приймає його запити на `127.0.0.1` |
    | `--email <address>` | Куди Let's Encrypt надсилатиме попередження про закінчення терміну сертифіката |
    | `--no-start` | Записати файли й нічого не запускати |
    | `--yes` | Не питати підтвердження, якщо каталог не порожній |
    | `--check` | Лише запустити перевірки системи та конфігурації |
    | `--uninstall` | Зупинити стек і видалити контейнери. Томи з даними лишаються |
    | `--purge` | Видалити встановлення разом із томами даних |

    ### Щоденні команди

    Запускайте їх із каталогу встановлення:

    | Команда | Що робить |
    |---|---|
    | `./railhook status` | Показує контейнери та їхній стан |
    | `./railhook logs [service]` | Показує логи в реальному часі, наприклад `./railhook logs api` |
    | `./railhook start` / `stop` / `restart` | Запускає, зупиняє або перезапускає стек |
    | `./railhook upgrade [version]` | Робить резервну копію, потім оновлює. Див. [Оновлення й резервні копії](/docs/uk/self-hosting/upgrade-backup/) |
    | `./railhook backup` | Записує дамп бази даних у каталог |
    | `./railhook doctor` | Повторно виконує всі перевірки для файлів на диску |

    Будь-який інший аргумент передається в Docker Compose, тож `./railhook ps` чи `./railhook up -d` працюють.
  </TabItem>
  <TabItem label="Docker Compose вручну">
    <Steps>

    1. **Завантажте Compose-файл і перелік налаштувань**

       ```bash
       mkdir railhook && cd railhook
       curl -fsSLO https://raw.githubusercontent.com/vadymkykalo/railhook/main/docker-compose.yml
       curl -fsSL https://raw.githubusercontent.com/vadymkykalo/railhook/main/.env.dist -o .env
       ```

    2. **Замініть публічні секрети**

       Значення в `.env.dist` загальнодоступні. Згенеруйте власні для кожної з цих змінних:

       ```bash title=".env"
       WEBHOOK_ENCRYPTION_KEY=   # openssl rand -base64 32
       WEBHOOK_ENCRYPTION_SALT=  # openssl rand -base64 16
       JWT_SECRET=               # openssl rand -base64 48
       POSTGRES_PASSWORD=        # must equal DB_PASSWORD
       DB_PASSWORD=
       REDIS_PASSWORD=
       ```

       Задайте в `APP_BASE_URL` і `CORS_ALLOWED_ORIGINS` URL, який відкриватимуть користувачі. `RAILHOOK_PORT` у цьому файлі — `8080`.

    3. **Запустіть із вбудованою базою даних**

       ```bash
       COMPOSE_PROFILES=embedded-db docker compose up -d
       ```

    4. **Перевірте, що все працює**

       ```bash
       curl -f http://localhost:8080/actuator/health/liveness
       curl -o /dev/null -w '%{http_code}\n' http://localhost:8080/api/v1/projects   # expect 401
       ```

    </Steps>

    <Aside type="tip">
    Щоб використати керовану PostgreSQL, приберіть `embedded-db` із `COMPOSE_PROFILES` і задайте `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER` і `DB_PASSWORD`.
    </Aside>
  </TabItem>
</Tabs>

<Aside type="caution">
Інсталятор закріплює теги образів у `.env` (`API_IMAGE_TAG`, `WORKER_IMAGE_TAG`, `UI_IMAGE_TAG`). У `.env`, створеному вручну з `.env.dist`, стоїть `latest`, а цей тег непомітно для вас переходить на нові версії. Закріпіть теги на конкретному релізі.
</Aside>
